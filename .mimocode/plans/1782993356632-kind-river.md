# 修复垂直标签栏 git 分支不显示的问题

## 根因

`fancy_tab_bar.rs:636` 通过 `get_foreground_process_info().cwd`（Windows 进程检查 / 读 PEB）获取 CWD。

这条路径在 Windows 上不可靠：`divine_process_list` → `with_root_pid` → 遍历进程树找最年轻子进程 → `ProcHandle::new(pid)` 打开进程句柄读 PEB 中的 CWD。如果 `OpenProcess` 失败（权限、架构差异等），`cwd` 为空 → git 分支无法检测。

与此同时，shell integration 的 precmd 钩子每次提示符前都会发送 `OSC 7;file:///...`，终端内部的 `terminalstate.current_dir` 已经有了正确的 CWD，且触发了 `CurrentWorkingDirectoryChanged` 事件刷新标签栏。**数据已经在手里，但代码没用。**

## 修复方案

**将 CWD 来源从进程检查改为 OSC 7（`get_current_working_dir`）。**

### 修改文件

`wezterm-gui/src/termwindow/render/fancy_tab_bar.rs` — 约第 634-638 行

**Before:**
```rust
// Use foreground process cwd directly — pane.title may have been
// modified by the running program (e.g. claude, codex) via OSC sequences.
let pane_cwd = pane_obj
    .get_foreground_process_info(mux::pane::CachePolicy::FetchImmediate)
    .and_then(|info| info.cwd.into_os_string().into_string().ok());
```

**After:**
```rust
// Use OSC 7 CWD (set by shell integration on every prompt) — this is more
// reliable than process inspection on Windows, where OpenProcess/PEB reads
// can fail due to permissions or architecture differences.
// Fall back to process inspection if OSC 7 hasn't been received yet.
let pane_cwd = pane_obj
    .get_current_working_dir(mux::pane::CachePolicy::FetchImmediate)
    .and_then(|url| url.to_file_path().ok())
    .and_then(|path| path.into_os_string().into_string().ok())
    .or_else(|| {
        pane_obj
            .get_foreground_process_info(mux::pane::CachePolicy::FetchImmediate)
            .and_then(|info| info.cwd.into_os_string().into_string().ok())
    });
```

### 验证方式

1. 编译 wezteam
2. 打开新终端，cd 到 git 仓库
3. 不运行任何命令，直接观察垂直标签栏是否立即显示 git 分支
4. 测试场景：
   - 新开标签页 → 立即显示分支
   - `cd` 切换目录 → 分支跟随更新
   - 运行 claude/codex 等修改 title 的程序 → 分支仍正常显示（因为走的是 OSC 7 不是 title）
5. 跨平台验证：macOS/Linux 上行为不变（这两个平台的 `get_current_working_dir` 已有可靠的 `/proc/<pid>/cwd` 回退）
