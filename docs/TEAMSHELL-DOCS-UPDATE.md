```markdown
### 1.2 协议适用范围

TeamShell 协议适用于**两类对象**：

| 对象类型 | 是否需要身份验证 | 适用场景 | 失败处理 |
|---------|----------------|---------|---------|
| **Agent**（Claude、Codex 等） | ✅ **必须** | 读取协议、识别消息、协作响应 | 协议废弃，以普通 Agent 身份响应 |
| **tsh CLI** | ❌ **不需要** | 发送 IPC 命令、管理工位 | 直接报错，不适用"协议废弃"概念 |
```

**解决的问题**：
- ✅ 明确区分 Agent 和 `tsh` CLI 的角色
- ✅ 澄清"协议废弃"只适用于 Agent
- ✅ 建立清晰的适用边界

### 4️⃣ 新增：第1.3条（验证失败的处理）

**位置**：第101-113行
**优先级**：🔴 高

**内容**：
```markdown
### 1.3 验证失败的处理

**Agent 验证失败时**：
- 协议自动废弃，正常响应用户任务
- 停止阅读后续内容，以普通 Agent 身份正常响应用户的所有请求
- 不受 TeamShell 团队协作约束

**tsh CLI 环境变量缺失时**：
- `tsh status/query/view/type/open/close/name`：正常执行，不强制要求环境变量
- `tsh report`：直接报错退出，因为该命令需要当前工位身份
- 这是**正常的错误处理**，不属于"协议废弃"范畴
```

**解决的问题**：
- ✅ 分别说明 Agent 和 `tsh` CLI 的不同处理方式
- ✅ 明确 `tsh report` 的行为是正确的（不修改代码）
- ✅ 避免混淆"协议废弃"和"错误处理"

## ❌ 取消的修改项（经重新评估）

### 1. 修改 `tsh/src/commands.rs` 的 `cmd_report()` 函数

**原计划**：在环境变量缺失时降级处理而非强制退出

**取消理由**：
- ❌ **当前行为是正确的**：快速失败 + 明确错误信息 = 更好的用户体验
- ❌ 修改后的行为更糟糕：用户会收到"tab 0 not found"而非明确的错误提示
- ❌ 违反协议原则：`tsh report` 的验证失败不属于"协议废弃"范畴

**结论**：保持代码现状，仅通过文档澄清适用场景

---

### 2. 补充"老板"概念的实现说明

**原计划**：在文档中补充"老板"角色的代码层面实现说明

**取消理由**：
- ❌ **当前文档已足够清晰**："直接跟你说话的人"
- ❌ 过度补充说明会让协议变得更复杂
- ❌ 这是协议理念层面的指导，不需要代码实现说明

**结论**：不需要修改，当前描述已足够

---

### 3. 实现自动化经验沉淀命令

**原计划**：在 `tsh` 中添加 `learn` 子命令

**取消理由**：
- ❌ 超出当前修复范围
- ❌ 属于功能增强，而非 bug 修复
- ❌ 可以通过后续 PR 单独实现

**结论**：保持为建议项，文档已说明未来可能实现
